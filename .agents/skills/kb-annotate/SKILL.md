# kb-annotate — 批注讲解循环

需求依据：`E:/ai/ku/knowledge-vault/网站/网页端需求.md`（v1.0）§6.2/§6.3。

## 0. 批注文件（数据契约，网站与 skill 共用）

位置：`E:/ai/ku/knowledge-vault/网站/批注/<笔记名>.md`

```markdown
---
note: "[[DLSS技术]]"
anchor: "核心概念·第2段"   # 原文锚点：节标题+段序
created: 2026-09-10
status: open              # open → explained → resolved
---

> 选中原文摘录…

### 我的疑问 | 2026-09-10 14:30
为什么运动矢量不用光流估计就行？

### 讲解 | 2026-09-10 14:31 · GLM
（讲解正文，贴着笔记上下文）

### 我的追问 | 2026-09-10 14:35
…
```

- 线程内多轮问答按时间顺序追加，**文件即会话记忆**——GLM 追问的上下文从这里取
- 网站前端负责：批注落盘、调 GLM、讲解回写。本 skill 负责：批量补讲、复盘、状态整理、升级问题

## 1. 上下文组装规则（与前端保持一致，改动需同步文档 §6.3）

按序拼装，总预算内从上往下带：

1. **L1 锚点段落原文**（必带）
2. **L2 笔记内容**：一句话总结 + anchor 相关节；笔记全文 <4000 字则带全文
3. **L3 双链邻居摘要**（可选，≤3 条，各一句话）
4. **L4 批注线程历史**（追问场景全带）
5. **System prompt 要点**：贴着笔记上下文讲，不编造笔记没有的内容；指出理解中对的/偏的（对齐 kb-ask 纠偏风格）；讲解收尾给 1-2 个相邻问题；中文

## 2. 凭据安全（硬约束）

`GLM_API_KEY` 只从环境变量或 `kb-site/.env` 读取；`.env` 必须在 `.gitignore`；**任何源码、示例、测试、文档、日志不得出现可用凭据字面量**。API 不可用时批注保持 `status: open`，讲解延后，绝不阻塞批注落盘。

## 3. 本 skill 的四个任务

### 3.1 批量补讲
扫描 `status: open` 的批注 → 按 §1 组装上下文 → 生成讲解 → 回写 `### 讲解` 节 + 状态改 `explained`。一次处理量告知维护者。

### 3.2 批注复盘
按笔记/领域聚合批注 → 找共性疑问（同一概念被批 2+ 次 = 笔记没写清）→ 建议回填原笔记（**建议**，改动走 kb-ask 定位写入流程，不直接改）。

### 3.3 升级为相邻问题
维护者说"这条批注值得深挖" → 按 kb-ask 问题日志格式追加新 Q 条目（原问题=批注疑问，状态 open），批注加一行「已升级为 Qxxx」。**不复制正文，用双链。**

### 3.4 状态整理
`explained` 且维护者无追问 → 问是否收 `resolved`；`resolved` 的批注在网站侧灰显。

## 4. 禁止事项

- ❌ 代写"我的疑问"（那是维护者的原话痕迹）
- ❌ 讲解脱离笔记上下文泛泛而谈
- ❌ 批注文件格式变动不同步前端与需求文档 §6.2
- ❌ 凭据落任何明文
